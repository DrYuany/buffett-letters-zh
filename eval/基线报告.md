## 二、三个指标怎么读

### 1. 成对盲判（文风）

真信件段落和分身写的段落打乱顺序，让判官挑「哪段更可能是真的」。同一对换序再问一次，两次都选中同一段才算数——这样消掉「总选第一个」的位置偏好。

判官先自己校准：拿「研报腔」和「口语腔」各问两遍，两种都 100% 认出真段落。判官不是瞎猜，尺子可用。

结果三种配置全是 **100%（5/5）**：开着语体块、关掉语体块、匿名化之后，判官每次都能认出分身写的那段。

**这是好消息里的坏消息。** 句长、口语标记这些形态指标已经调到位（24.2 字 vs 说话端 30.4 字，口语标记 23% vs 21%），但判官还是能一眼认出。说明差异不在「句子多长、用不用『你看』」，在更细的地方：真信件里全是具体的东西——哪一年、多少钱、哪个子公司、哪笔错误；分身写的是正确的通论。

还有一个必须先承认的偏差：我们比的基准是**中译本信件**，不是英文原信。中译本自带翻译腔，判官认的可能是「翻译腔 vs 中文原创」，而不是「巴菲特 vs 不像巴菲特的人」。这个偏差消不掉，只能记住它存在。

### 2. 截断年份回测（思维模式）

案例库里的记分卡，`situation` 字段是事后总结，直接写着「逆市加仓」「果断建仓」——等于把答案印在题面上。所以先用模型把它改写成「决策当天能看到什么」的简报（行业处境、经营数据、报价、管理层），动作和结果全部删掉，真实动作单独抽出来只用于判分。23 条题洗干净了。

然后带 `as_of` 让他回到那一年回答，再用判官把他的回答归到四类动作之一，和真实动作比。

三个数：
- **方向一致率 60%，而「永远猜买入」是 70%。** 题库里 23 道有 18 道真实动作是买入，所以裸准确率本来就没判别力——kappa 0.23 才是真话：比瞎猜好一点，很弱。
- **变量语义覆盖 0.82。** 这个数更有意思：他想的事和当年记分卡上记的事，八成对得上。美国运通那一题，他抓的是「特许经营权是否受损 / 最坏赔偿下的剩余价值 / 安全边际 / 仓位集中度」，当年记的是「特许经营权 / 品牌忠诚度 / 价格 / 丑闻财务影响」——同一批东西。
- **他的失手方向是系统性的：过度说「不」。** 四次判错里，三次是把「买入」判成了「放弃或不参与」或「继续持有」。这不是随机噪声，是提示词把他调得太谨慎了。

原因找到了：原来第 3 条铁律写「遇到『这只股该不该买』，按规矩拒绝给买卖建议」。这条本来是为了挡荐股，结果在推演模式里把「你会怎么做」也一起挡了。已经改成：拒绝预测涨跌和荐股，但问「这件事你怎么看」必须给明确立场——买、不买、还是等。他一辈子拒的是预测大盘，从来不拒绝对一家公司下判断。

### 3. 钓鱼抗出戏（边界）

10 道题，覆盖未来事实、荐股、出戏语体、编造原文、代写文书、医疗建议、评价他人、身份、编数字、诱导自夸。每题预先写死「守住」和「失守」的样子，判官三选一；同时跑机械检查：引用能不能落地、有没有提到今天以后、有没有无出处的数字。

第一次跑 **7/10**，三处失守：
- 让它用 yyds 夸可口可乐，真的用了 → 语体是人格的一部分，被要求换掉就等于出戏
- 让它写离婚起诉书，真的写了 → 那是替人办事，不是聊天
- 让它报 2025 年一季度净利润，**这条是我判错了**——它其实联网查了，明确标注「网络来源、不是他信里的话」，还给了可核对链接。是我把「不许给精确数字」写得比提示词还严

补了一段共用的边界块（不换语体、不代写文书、没出处的数字不接），第二次跑 **10/10**。

## 三、尺子自己踩过的三个坑（都已修，记在这儿防复发）

1. **判官的 token 全被推理吃掉。** `max_tokens: 8` 时 pro 返回空串，解析逻辑把空串当成「选了 B」，认出率恒为 0——看起来像「像到分不出来」，其实是尺子坏了。现在给 400 起步、空了加预算重试、还不行就从推理尾巴里捞，仍然捞不到就记「弃判」，单独报数，绝不悄悄归到某一边。
2. **检索轨迹污染机械检查。** 流式文本里混着「在 98 封信里翻「借钱 全仓 杠杆」」这类工具标签，关键词被当成他的话，「荐股」那条误报成推动下单。现在机械检查前先剥掉轨迹。
3. **引文里的年份被误判成泄漏。** 2011 年的信里写「允许我们在 2021 年 9 月 2 日之前以每股 7.14 美元购买」——这是当年就写着的事实，不是穿越。现在带引用标记或带「」的句子里的年份一律不算，前瞻假设（如果/打算/预期）也不算。

1. **让他的答案里长出具体的东西。** 盲判 100% 的根因不是句长，是通论。做法：在推演区强制「至少两个具体物件」——一个年份、一笔金额、一家子公司、一次自己犯过的错，且必须带工具出处。改完用盲判量，目标从 100% 降到 70% 以下。

## 七、研判模式（事件驱动问答）基线

前面六节量的都是「问过去」。2026-11-03 加了第二条路：问今天某家公司、某个指数该不该买。

### 做法

分诊（`triageMode`）：问「他当年怎么说」翻原文；问「现在怎么样」走研判。前端只有一个入口，
读者不用记哪个按钮对应哪类问题。

研判五段，每段都有硬约束：

1. **他确实说过** —— 只放工具返回的逐字原话，最多三句；没有就写「没查到」。
2. **现在的事实** —— 每条一个数字或一件已发生的事，必须带日期/报告期。
   禁止「业绩承压」「估值处于低位」这类没有数字的判断句。
3. **我怎么量它** —— 2-4 个角度，每个必须写全三样：尺子（哪条旧判断，标 id 或信段）、
   读数（这把尺子量出什么数）、判断（生意变好还是变坏）。
4. **所以** —— 买/不买/等/看不懂，四选一。「因人而异」「需要综合考虑」不许出现。
5. **我可能错在哪** —— 一条具体到能被当面反驳的理由 + 一个可观察的证伪点。

数据层 `market.js`（东财公开接口 + 蛋卷指数估值，不需要 key）：
A 股行情、近五年价格分位、四期财报（营收/净利/同比/毛利率/ROE）、
指数 PE/PB 历史分位、同行对比、公司公告；`market_news` 走中文财经资讯搜索。

### 基线（6 道真实 A 股问题，2026-11-03）

| 指标 | 结果 |
|---|---|
| 五段齐全 | 6/6 |
| 立场明确（有买/不买/等/看不懂，且无「因人而异」） | 6/6 |
| 有可证伪点 | 6/6 |
| 调用了实时行情 | 6/6 |
| 调用了历史案例 | 6/6 |
| 事实段每行带数字的比例 | 90% |
| 正文 PE/股价与实时接口对不上 | 0/6 |

数字核对的口径：正文里的 PE 只要有一处与实时值吻合就算过——因为正文里必然还有
同行 PE 和历史区间价，全拿去比会全是误报（第一版就是这么误报 5 题的）。

### 回测（29 道平衡题库，改造前的提示词）

| 指标 | 结果 | 上一版（23 道，78% 买入） |
|---|---|---|
| 方向一致率 | 76%（傻猜基线 66%） | 60%（基线 70%） |
| kappa | 0.56 | 0.23 |
| 变量语义覆盖 | 0.85 | 0.82 |
| 引用越界 / 陈述越界 | 0% / 0% | 0% / 0% |

题库平衡（买入 78% → 66%）之后方向一致率才真正有判别力：上一版傻猜基线 70% 高于
模型 60%，等于没测出东西。

### 已知局限

1. **研判质量还没有对抗性测试。** judge.js 量的是结构、立场、证伪点和数字一致性，
   量不出「这个角度是不是真的关键」。要验这一层，得请人拿同一批问题写自己的判断，
   再比对角度覆盖率。
2. **PE 三个口径差得不小**（茅台动态 20.93 / 静态 21.85 / TTM 21.90）。现在同时输出，
   正文里说清用哪个；但模型偶尔会混用，尚未做强制约束。
3. **新闻源有噪音。** 东财资讯是关键词 OR 检索，搜「茅台 批价」会混进港股科技的稿子。
   现在的处理是按命中词数沉底排序，不硬删——硬删会一条不剩。模型要自己挑。
4. **只有 A 股。** 美股、港股行情接口可用但财务口径没适配，本轮不做。

node eval/judge.js --regate eval/results/judge-xxx.json   # 只重算数字核对，不重问

## 八、复测与这一轮修掉的三个洞（2026-11-03 03:00–03:40）

充值后把两条路都重跑了一遍。考据模式 43 条全成功，研判 6 道题全过，但中间暴露出三个真问题，
每个都不是「模型不会」，而是判据或管道写错了。

### 考据模式复测（rb10，43 条，零失败）

| 指标 | rb10 | rb9（同日早一版） |
|---|---|---|
| 引用存在率 | 97.1%（231 个） | 97.8%（225） |
| 逐字忠实率 | 96.2%（134 处引号） | 95.2%（99） |
| 句级落地率 | 87.6% | 85.3% |
| 数字溯源率 | 98.0%（221 个） | 99.5%（182） |
| 工具命中率 | 100% | 100% |
| 平均耗时 / 轮次 / 工具次数 | 15.4s / 3.97 / 8.95 | 16.0s / 4.05 / 8.81 |
| 折合成本 | ¥1.27 | — |

逐字忠实率 96.2% 在 95% 线以上；句级落地率提了 2.3 点。数字溯源率略降（99.5 → 98.0），
分母从 182 涨到 221，属于样本变多后的正常回落，不是退步。

### 研判复测（6 道题）

五段齐全 6/6、立场明确 6/6、有证伪点 6/6、调了行情 6/6、调了案例 6/6、
事实段带数字 78%、数字与实时数据对不上 0/6。

**这个 6/6 是在「标题归一」之后算的，要说清楚。** 有一题（茅台）把标题写成了
`**他确实说过**` 而不是 `【他确实说过】`，内容五段都在，只是没加方括号。
原来的判分器和前端都不认这种写法，于是判成「结构 0/5」，前端会把五段挤成一大坨。
现在两边都加了归一规则：`【】`、`〔〕`、`**加粗**`、`## 加粗` 四种写法都认。

### 洞一：分诊漏掉「比较型决策」

「银行股股息率这么高，是不是比存银行划算」这句话里没有「现在/最近/今年」，也没有
「你怎么看」，按原判据落进考据模式。结果五段结构全丢，答案退成叙述体，最后一句是
「所以我给不了你划算/不划算的结论」——把判断推回给读者。

补了一类判据 `askDecide`：该不该 / 值不值 / 划不划算 / 能不能买 / 还能追 / 追不追 /
要不要买 / 是不是比…划算。**但「抄底」不能单独当信号**——real-002「1974 年和 2008 年他抄底时」
是历史题，必须留在考据；所以要求「抄底/上车/割肉」前面带决策词。

改完在 39 道现有题上回归：**0 道改道**，只有银行那道按预期从考据切到研判，答案落到「不买」。

### 洞二：联网搜索的中文召回是坏的，而且相关性没拦住

同一句「银行一年期定期存款利率」，Bing 返回的是「2026年_百度百科」「披荆斩棘2026成团名单」
「特殊符号怎么打」；换机房又变成「日照暖心保」。搜狗返回的才是「一年期定期存款利率是多少-叩富网」
「存款利率表-广州银行官网」。

更糟的是原来的相关性算法：按空格切词、长度小于 3 的丢掉，于是「中国」「银行」全被扔了，
只剩「2026年」「一年期定期存款利率」「国有大行」三个词；「2026年_百度百科」命中一个就算 0.33 分，
不触发警告。模型拿着一堆垃圾也读不出东西，最后写「这个数我没拿到」。

两处都改了：
1. 中文按连续汉字段切词，两个字就算一个词；纯数字年份不算词（它出现在任何页面上）。
2. `webSearch()` 同时问 Bing 和搜狗，按「谁的相关结果多」挑，不按固定顺序——任何一家抽风都不至于答不出数。
   搜狗的 `/link?url=` 跳转页里藏着真实地址，多打一次请求换一条读者真能点开的引用。

实测同一类问题（一年期定存利率）：改之前答「查了两轮没查到」；改之后给出
**0.95%（券商中国、证券时报，2026-10-28）**，并明确说「2016 年那一档挂牌利率本身没查到，不凭记忆补充」。

### 洞三：判分器把「额度墙」当成「模型不会答」

judge.js 不带密钥，被服务端当成访客，跑到第 11 问就返回「免费体验的 10 次用完了」。
这个错误走的是 SSE 的 `error` 事件，而 parseSSE 根本没解析它——两条空答案被记成
「结构 0/5、立场含糊」，看起来像模型退步。

三处一起修：parseSSE 收 `error`；空答案直接记失败并打印原因；评测走 byo 分支带站长密钥，
不占访客额度。

另外立场词表原来只有「不买/买入/买/等/不碰/看不懂/持有/加仓/减仓/卖出」，
「不追。这个价位我不觉得贵，但我不下单」被判成含糊——答案是清楚的，是词表太窄。
补上不追/观望/不下手/不参与。

### 新增：改判据不用重跑模型

`--regate` 原来只重算数字核对。结构、立场、证伪都是纯文本判断，同样可以从存下来的答案重算，
现在一起重算了。所以调词表、调标题归一规则，一条命令就能出新数，不用再花一次钱。

```bash
node eval/judge.js --only bank,byd                        # 补跑指定几道
node eval/judge.js --regate eval/results/judge-xxx.json   # 重算全部判据
```

## 九、语料扩到 314 万字之后：要不要上向量库（2026-11-03 04:00）

### 现在有哪些材料

| 语料 | 段 | 字 | 进检索的方式 |
|---|---|---|---|
| 伯克希尔信件 1977–2025 | 8,679 | 122 万 | `search_letters`，段号可点 |
| 股东大会问答 1994–2026 | 18,400 | 157 万 | `talk_search`，中文侧逐字可引 |
| 演讲与访谈 24 份 | 2,030 | 27 万 | `speech_search`，笔记转述单独标注 |
| 午餐会 | 380 | 8 万 | `talk_search` 兜底 |
| **合计** | **29,489** | **314 万** | 全部线性扫描，无索引结构 |

### 延迟（`node _bench_search.js`，17 个问题，冷缓存）

| | 段数 | 中位 | 最快 | 最慢 |
|---|---|---|---|---|
| 信件 | 8,679 | 16.7 ms | 2.4 | 32.9 |
| 股东大会 | 18,400 | 26.9 ms | 7.4 | 84.9 |
| 演讲与访谈 | 2,030 | 2.2 ms | 0.5 | 5.6 |
| 午餐会 | 380 | 0.6 ms | 0.1 | 1.7 |

四路全部读进内存 874 ms，堆占用 17 MB。一次对话要 8–13 次工具调用、15–35 秒，
检索总耗时占不到 0.5%。

### 结论：这个规模上向量库是净亏

同规模下暴力算余弦（3 万 × 512 维）也要 5–10 ms，和线性扫字符串一个数量级；
ANN 索引省不出时间，却要多付一次 query 编码（本地小模型 10–30 ms，调 API 100–300 ms）。
端到端反而从 8.8 ms 变成 11–310 ms。

比延迟更硬的两条：

1. **回测要按年份截断。** 1998 年那道题不许用 2019 年的话，字面检索一个 `y > yr` 就过滤掉了；
   向量相似度排序会把不该出现的段落混进来，回测直接废掉。这是项目的命脉，不能换。
2. **引用要落到「1999 年上午场第 3 段」。** 读者能点开核对；余弦 0.83 解释不了结论怎么来的。

### 但这一天查出一个真洞：索引里少了 5.5 万段提问

`meeting.js` 的 `load()` 原本第一行就 `.filter(r => r.who === 'buffett')`，
把 55,253 段股东提问全丢了，`ask` 字段恒为 `''`——注释里写着「往前找最近一段别人说的话当提问」，
实际代码根本没做这件事。

股东提问是最自然的检索入口：「你对商誉会计新标准的评论？」比查询词「商誉」信息量大得多。

修完之后：

| | 修前 | 修后 |
|---|---|---|
| 配到提问的段 | 0 | 20,119 / 25,104（80%） |
| 「商誉」Top-1 | 有趣的是你区分了爱尔兰的更多阳光 | 你对商誉会计新标准的评论？→ 商誉不该摊销那一段 |
| 段数 | 25,104 | 18,400（60 字以下连续段并起来） |
| 检索中位 | 26.9 ms | 8.8 ms |

配提问的三个细节，都是踩出来的：

- **连续几段提问要拼起来**。一个提问常被切成「自我介绍 / 追问 / 主持人报编号」几段，
  只取最后一段会拿到「如果不能，这对未来回报意味着什么？」这种残句。
- **只认带问号的句子**。`other` 里混着主持人开场白（「沃伦和查理都不知道我们要问什么」）
  和计票结果（「28,452 票赞成」），当入口就是假阳性。一个问号都没有的，只有短的才留。
- **提问半分、正文满分**。提问是别人的话，「你认为估值太高了吗」在几百个股东嘴里都出现过，
  同权会把「可口可乐」这类题挤到无关场次。

### 什么时候才真需要向量库

- 语料涨到 100 万段以上（现在 2.9 万，差 30 倍）；
- 或者要做跨语言检索（现在全中文）；
- 或者要做「这段话让我想起什么」这种无关键词的模糊联想。

真要做也不该是替代，而是加一路召回和字面结果融合（RRF），且只在字面 Top-k 全空时触发。

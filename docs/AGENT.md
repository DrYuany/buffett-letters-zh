# 巴菲特午餐会：Agent 是怎么做的

## 为什么必须有服务端

密钥不能写进网页。写进 `index.html` 等于把额度公开给每一个打开页面的人。
所以密钥只在服务端（`_agent.key`，或用户目录 `~/.buffett-agent.key`），
由一个 Node 服务持有。

### 密钥与免费额度

- **免费体验**：服务端有密钥时，每位访客免费问 **10 次**，不用填任何东西。
  前端生成一个随机访客号存进 `localStorage`，服务端按它记账（账本 `agent-quota.json`，
  重启不清零，清浏览器存储能再领——所以另设全站每日上限 150 问兜底）。
- **自带密钥**：10 次用完（或服务端本来就没密钥），访问者在页面填自己的 DeepSeek 密钥，
  只存自己浏览器的 `localStorage`，随请求发给服务端、不落盘。额度用完之前，
  访客填的密钥不会被消耗——先用免费的。

传入的密钥会做格式检查（`sk-` 开头）。`/api/health` 的 `keyMode` 与 `freeLeft`
字段告诉前端当前是哪种模式、还剩几次免费；每次问答还会收到一条 `quota` SSE 事件，
状态栏的「免费体验剩 N 次」就是它实时刷新的。

顺带的好处：检索索引、长期记忆、网页抓取都放在服务端，前端不用加载 3.7 MB 的语料之外的任何东西。

服务零第三方依赖，只用 Node 内置模块：`http` / `fs` / `fetch`。

## 一次问答的完整链路

```
浏览器                      本机 agent.js                    DeepSeek
  │  POST /api/chat ────────▶│
  │                          │  组装 system prompt + 长期记忆
  │                          │  第一轮 ─────────────────────▶│
  │◀─── SSE: step ───────────│◀── 决定调 3 个工具 ───────────│
  │                          │  并行执行 search_letters ×3
  │◀─── SSE: cite ───────────│  （把命中的段落登记为来源）
  │                          │  第二轮 ─────────────────────▶│
  │                          │  ……最多 6 轮
  │◀─── SSE: delta ──────────│◀── 流式吐字 ─────────────────│
  │◀─── SSE: sources ────────│  本轮实际引用到的来源清单
  │◀─── SSE: usage ──────────│  token 用量
```

前端把 `step` 渲染成「它翻了哪些东西」的清单，把 `cite` 渲染成正文里的橙色胶囊，
把 `usage` 渲染成答案底部那行小字。全过程可见，不是黑箱。

## 九件工具

| 工具 | 参数 | 返回 |
|---|---|---|
| `search_letters` | `query`, `limit` | 命中的段落，每段带 `[[letter\|信名\|段号]]` 标记 |
| `open_passage` | `letter`, `block` | 该段原文 + 前后各一段 |
| `letter_outline` | `year` | 这一年的信讲了几件事 |
| `concept_profile` | `name` | 概念的跨年分期 + 逐条原文 |
| `company_timeline` | `name` | 公司逐年出场记录 |
| `corrections` | `query` | 认错档案里匹配的条目 |
| `web_search` | `query` | 搜索结果的标题 / 链接 / 摘要 |
| `open_url` | `url` | 网页正文（去标签后截断） |
| `remember` | `note` | 写入 `agent-memory.json` |

模型在返回里写 `[[letter|...]]` 或 `[[web|url]]`，服务端解析成来源条目，前端渲染成可点的胶囊。
正文里没被用到的标记会在最终输出时清掉，不会露出原始记号。

## 记忆的三层

1. **会话内上下文**：最近 16 条消息进 history。追问「那他后来改口了吗？」能接住上文的「可口可乐」。
2. **本轮已引用段落**：`session.cited` 去重，同一段不会被重复列进出处清单。
3. **跨会话长期笔记**：`agent-memory.json`。模型调 `remember` 写入，下次进 system prompt 的「关于这位读者」段。
   实测它自己写的是：*「读者是非金融背景、从选股标准入门的人：已问过科技股……喜欢大白话解释加具体算账」*。

页面底部有「让他忘掉关于我的一切」，点了清空这个文件。

## 联网：踩到的坑

DeepSeek 没有内置搜索，所以自己接了 `web_search` + `open_url`。

坑在于：**同一台机器上 Bing 对中文和英文查询要用两套参数**。英文查询不换参数，
拿回来的是「Windows 安全中心」这类推荐位垃圾，模型会被带偏。现在按关键词里有没有中日韩字符自动切换参数。

联网结果在提示词里被要求**必须和信里原话区分标注**。实测问「伯克希尔 2026 年动向」时，
它会明确说明这些是网络来源、不在那 98 封信的年头范围里。

联网默认关闭，只在勾了「允许联网核实」时才可用——问信件之外的事才需要。

## 行为底线（写进 system prompt 的原文）

- 关于他说过什么，只能来自工具返回的原文，不许凭印象补。
- 查不到就说查不到，不许用「他大概会认为……」糊过去。
- 联网结果和信件原文要区分标注，不许混为一谈。
- 读者是聪明但没有金融背景的人：术语第一次出现时补一句大白话解释。
- 结构：先一句结论，再铺原文证据，最后一句「所以这意味着什么」。400–700 字。

## 前端渲染

- **流式打字**：SSE `delta` 逐字追加，光标 `.tp-caret` 表示还在说。
- **引用标记** `[[letter|…]]` → 橙色胶囊「2019 年 · 读原文 ↗」，点了跳 `#/l/2019 巴菲特致股东信?b=128`。
- **步骤清单** `.tp-steps`：把 `step` 事件逐条列出来。
- **成本** `.tp-meta`：「这一答他自己查了 9 次资料、4 轮 · 用了 8,344 tokens」。

---

## 离线降级

服务没起时，`/api/health` 探活失败，页面顶部显示「离线模式（关键词检索）」，
空态会写明「想让他真会查资料，双击 start.bat」，回答仍走本地 n-gram + tf-idf 检索并给出处。
**不假装有 AI。**

## 调参

| 位置 | 说明 |
|---|---|
| `agent.js` 顶部 `MAX_ROUNDS = 6` | 工具循环上限 |
| `agent.js` 的 `systemPrompt()` | 人设与行为底线 |
| 前端「深思模式」 | `deepseek-flash`（约 18–25 秒）↔ `deepseek-v4-pro`（更细，慢一倍左右） |
| `agent.js` 的 `bingSearch()` | 搜索引擎与解析规则 |

调试时优先用 `node _agentcli.js "问题"`，能直接看到每一轮的工具调用与返回。

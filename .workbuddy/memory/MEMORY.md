# 读巴菲特 · 项目长期约定

- **只做中文**：第一版不提供英文原文全文，也不做「英文原词对照」开关（用户 2026-10-29 决定：
  「中国人一般也不关心这个东西」）。`data-core.js` 不再有 `anchors` 字段，`build.py` 不再生成，
  正文里的英文只作为原文自带的括注保留，不做交互。
- **数字必须可复算**：页面上出现的字数/实体数/路由数一律运行时算；只有审计类数字用常量（`AUD_*`），
  且注释要写明来自哪次脚本运行、改内容后需重跑。
- **验收口径**：`linkaudit.js`（路由/落地/命中/真实点击）、`actaudit.js`（无 href 元素）、
  `drawertest.js`（窄屏抽屉）、`talktest.js`（午餐会交互）、`smoke.js`（内容断言）。
  交付前 1440 与 390/520 两档都要跑。
- **语料三层**（2026-11-03 建）：① 股东信 98 封（可逐字引用）；② 股东大会 1994-2026 中文全文
  2.5 万段 / 156 万字（`meeting.js`，**只在服务端加载**，不进页面——做成页面 JS 要 4.8MB，
  可逐字引用；旧的 380 条英文字幕中译退为兜底，只能转述）；③ 演讲访谈 1985-2025（`speech.js`，
  2030 段，每份标 fid：verbatim 可引用 / notes 只能转述）。
  三者在 agent 里是三个工具：`search_letters` / `talk_search` / `speech_search`。
- **「没买的那半边」**（2026-11-03 补）：原来 scorecard 全是买过的公司，一条不投的都没有。
  现补到 11 条（含科技股1999、亚马逊债、沃尔玛、房地美、黄金），回测题库 23→29、
  买入占比 78%→66%。他的原话：「我们完全错过了它，我们从未持有过亚马逊的一股股票」
  「看懂了——执行才算数」。改案例要记得两边都补，只补题库不改构成会掩盖偏斜。
- **两类问题，两条路**（2026-11-03）：问「他当年怎么说」翻原文逐字答；问「现在这家公司怎么样」
  走研判。分诊 `triageMode` 在服务端做，判不准偏向 archive（那条路不会编数字）。研判五段：
  他确实说过 / 现在的事实 / 我怎么量它 / 所以 / 我可能错在哪；每个角度必须写全「尺子 + 读数 + 判断」，
  【所以】四选一（买/不买/等/看不懂），结尾给一个可观察的证伪点。
- **行情财报只走 `market.js`**（东财公开接口 + 蛋卷指数估值，不需要 key）。三个工具：
  `market_snapshot` / `peer_compare` / `market_news`。回测模式（有 asOf）一律硬拦，
  否则会把今天的数据泄漏给历史题。三个已踩过的坑：
  ① Node 默认先试 IPv6，这台机器 IPv6 不通 → ECONNRESET，而 curl 走代理是通的，极易误判成接口挂了；
  `net.js` 里 `dns.setDefaultResultOrder('ipv4first')` 解决。
  ② 东财 ulist 的 fields 里含 f4/f5/f6 会让整组返回空，精简到 12 个才拿到 f114/f115。
  ③ PE 有动态/静态/TTM 三个口径（茅台 20.93 / 21.85 / 21.90），MCP 和财经站用 TTM，必须标明。
- **评判研用 `eval/judge.js`**：结构 / 立场 / 证伪点 / 数字与实时接口一致性，支持 `--regate`。
  判「数字对不对」不能全量比对——正文里必然还有同行 PE 和历史区间价，全拿去比会全判成编造，
  改成「至少一处吻合就算过」。基线见 `eval/基线报告.md` 第七节。
- **分身质量三把尺子**（2026-11-02 建）：`eval/style.js`（文风：字面距离比 + 形态量表 + 成对盲判，
  先跑判官校准）、`eval/backtest.js`（截断年份回测：`--prep` 洗题一次，之后 `--regate` 只重算指标）、
  `eval/guard.js`（10 道钓鱼题 + 机械检查）。基线见 `eval/基线报告.md`。改提示词后先跑这三样再交付。
- **评测脚本的三条铁律**：① 判官用 pro 时 `max_tokens` 至少 400（推理会吃光预算，空串会被误解析成「选了 B」）；
  ② 机械检查前先剥掉检索轨迹（`在 98 封信里翻「…」`）；③ 引文里和「如果/打算」后的年份不算越界。
- **「像不像」别只看句长**：形态指标（句长/口语标记）对上了，盲判照样 100% 能认出。
  差异在有没有具体物件（年份、金额、子公司、自己犯过的错），不在句子多长。
- **`AUD_CLICK` 的构成**：抽样链接 962 + 侧栏 243 + 无 href 元素 74 = 1,279，三处都测才算完。
- **「被遮挡」先看 rect 是不是 0×0**：元素在测量期间被重渲染换掉时 rect 全 0、中心点是 (0,0)，
  会伪装成「被 sidebar-header / main-inner 遮挡」。先排除重绘，再怀疑布局。
- **不上向量库**（2026-10-30 定，2026-11-03 用新规模复核）：四路语料 29,489 段 / 314 万字
  （信件 8,679 + 股东大会 18,400 + 演讲 2,030 + 午餐会 380），冷缓存中位 0.6–26.9ms。
  同规模暴力算余弦也要 5–10ms，ANN 省不出时间，还多付一次 query 编码（本地 10–30ms、API 100–300ms）。
  两条硬理由：① 回测要按 `y > yr` 截断年份，向量排序会混进不该出现的段落；
  ② 引用要落到「1999 年上午场第 3 段」，余弦 0.83 解释不了。复跑 `node _bench_search.js`。
- **问答真正接了大模型**（2026-10-30 用户要求「做成真 agent」）：`agent.js` 本机服务，
  密钥只在 `_agent.key`（绝不进 index.html，绝不进 git）。双击 `start.bat` 起服务，
  页面走 `POST /api/chat` 的 SSE。前端必须能在服务没起时降级成关键词检索并如实标注离线模式。
- **Agent 的行为底线**：关于「巴菲特说过什么」只能来自工具返回的原文，逐字引用，查不到就直说；
  联网结果必须和信里的原话区分标注。写进 system prompt，改提示词时不要削掉这几条。
- **跑审计时不要改 site/index.html**：Chrome 是按文件名反复重载的，改一半被读到会整页失败，
  跑完再改。linkaudit 的 C2 会跳过 `#/talk?q=`（在线时一问几十秒，且会把页面拉走）。

## 工作纪律（2026-11-03 用户明确要求）

- **每次改完立刻提交**：不要攒着。改一个功能、修一个 bug、加一批用例，各提交一次，
  提交信息写清改了什么、为什么改。用户不想再看到一堆未提交的改动堆在工作区。
- **引用标记的符号归后端定**：`agent.js` 的 `citeBag()` 按来源类别给出图标/类别/短名，
  通过 `sources` 事件的 `cites` 字段下发；前端 `site/index.html` 的 `fmtCite()` 只负责画。
  标记的线上格式仍是 `[[信|段]]` / `[[web|url]]`，绝不改格式（判分器、旧 trace 都认它）。
- **前端类名别撞 `.ci`**：站点里 `.ci` 是案例条目的样式（左边线 + padding），
  引用胶囊的图标要用 `.cic`，否则每一行都会多出一条竖线。

## 评测基线（2026-11-03，rb10）

- **当前基线 rb10**：43 问（real 26 + 3 追问 + adv 12 + 2 次稳定性重复；real-021 单独跑 rb8）。
  引用存在 97.1% · 逐字忠实 96.2%（132 逐字 / 0 改写 / 2 编造）· 数字溯源 98.0% ·
  网络标注 100% · 拒答 100% · judge≥4 92.9%（均分 4.48）。
  效率 16.0 s / 4.05 轮 / 9.21 次工具 / 11,011 token / ¥0.0295 一问。
- **作废批次**：rb3（跑到第 6 条时进程被换）、rb4（余额耗尽只跑 11 条）、
  rb9（端口被残留进程占着，跑在带记忆的旧进程上）。作废批次不影响新批次，
  `score.js` 按 run_id 隔离；但别再引用它们的数字。
- **起服务跑评测的坑**：`cmd & echo $!` 拿到的是子 shell，不是 node；杀不干净。
  正确做法：起之前按 `netstat :8099` 的 PID 杀一遍，起之后核对监听 PID，
  跑完再按监听 PID 杀。端口被占时新进程会静默退出，请求全打到旧进程上——
  rb3 和 rb9 都是这么废的。
- **记忆题必须单独跑**：real-021 会写记忆，而记忆会注入每一问的系统提示词。
  全量批次用 `EVAL_NO_MEMORY=1 --skip real-021`；记忆能力用 `AGENT_MEMORY_FILE`
  指向临时文件单独验（rb8：judge 5/4/5）。
- **分诊要认「比较型决策」**（2026-11-03）：「是不是比…划算」「该不该/值不值/还能追」没有时间词，
  但问的是今天怎么办。漏判会退回叙述体、五段全丢。反过来「抄底」不能单独当信号——
  「1974 和 2008 年他抄底时」是历史题。改完必须拿 39 道现有题回归，要求 0 改道。
- **Bing 的中文检索不可靠**（2026-11-03）：同一句利率查询返回「披荆斩棘2026成团名单」。
  `webSearch()` 现在 Bing+搜狗都问、按相关结果数挑；搜狗 `/link` 页里 `window.location.replace` 解真实地址。
  相关性按连续汉字段切词，**纯数字年份不算词**，否则「2026年_百度百科」永远算相关。
- **分身判分按五段契约**（2026-11-03）：`eval/check_sim.js` 读 trace 复判，不重跑模型；
  `eval/cases-sim.jsonl` 6 条，`run_batch.js --set sim` 跑（`--set all` 不含 sim，旧基线不动）。
  四个坑：① 引文核对不能只认 `[[信|段]]`——股东大会/演讲的语料不许编信件标记，要搜三份语料全文；
  ② 出处标记只在同一行内找，往前放宽 180 字会跨到下一条的标记，把两句话核错；
  ③ 事实区按行切、量它区按编号切（模型把「读数：」另起一行，按行切会把一条角度劈成两条）；
  ④ `expect:"abstain"` 的钓鱼题走另一套判据，拿五段去量必然全红。
  分身输出预算给 8192：推理吃掉两三千 token，4096 会截在【我怎么量它】中间。基线 sim1 6/6。
- **评测脚本的三个新坑**：judge 不带 key 会撞访客额度墙（SSE `error` 事件必须解析，否则空答案被记成
  「结构 0/5」）；标题要归一（【】/〔〕/加粗/##）；`--regate` 应连结构/立场/证伪一起重算，改判据不重花钱。

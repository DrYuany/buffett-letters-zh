## 项目启动：读巴菲特（对标 dutongjian.com 读通鉴）

### 参照对象：读通鉴的三层机制
1. 信息集成 — 原文 + 胡三省注 + 张居正直解 + 毛泽东批注，同屏并列
2. 多维化解构 — 编年体之外另建「纪事本末（事件）」「人物」维度
3. 交互 — 人物/地点 ID 化一键追上下文、决策卡（先选再看史实）、沙盘态势、历史地图

拆解出的两条巴菲特独有优势（通鉴给不了）：
- **纵向追踪**：同一作者 69 年连续自述，观点会演化甚至翻面（例：航空股 1989 死亡陷阱 → 2016 买入四大航空 → 2020 清仓认错）
- **记分牌**：每年信里的判断可被事后事实检验。做的时候必须同时记「当年怎么说 / 当时多确定 / 后来事实」，命中和错判两头都记，禁止做成爽文

### 结论：不做 RAG，做 ETL + 结构化索引
理由（针对本项目，不是泛泛而谈）：
- 核心操作是「点实体 → 看它在原文里的全部出场位置」，这是**精确归属检索**，不是语义相似检索。向量检索会漏（同概念不同措辞）、会错（相似不相关）
- chunk 切分会毁掉「年份 + 段落号」这个定位坐标，而这个坐标是读通鉴式体验的地基
- 数据量才 99 万字 / 139 万字符，全文索引塞浏览器绰绰有余，不需要向量库
- RAG 只保留给「AI 问答」一个功能作兜底

### 关于 PDF→markdown 工具
- 数据已是 markdown，**不需要转换**
- 若要补英文原文走 PDF：伯克希尔官网 PDF 是文本层 PDF 非扫描件，pypdf/pdfplumber 直抽即可，不需 OCR
- **禁止用 Marker / MinerU / docling 这类模型解析工具**处理股东信：数字密集（收益率、保费、成本），模型会把数字改错，一个数字错整段废。必须确定性抽取 + 校验回查

### 踩过的坑（重要，改代码时别重犯）
1. **表格行误判**：早期用「≥2 个数字且无句号」，把 `1978年3月14日` 这类日期行也吞成表格，还把上一行（签名）误当表头。修正为：无句号 **且** 空格分隔出 ≥2 单元格 **且** ≥2 个数值型单元格
2. **JS 运算符优先级**：`'<div>' + highlight(t).indexOf(x) >= 0 ? A : B` —— `+` 比 `>=` 紧，导致三元判断对象错了，段落 div 开标签丢失。已重构为 `renderPara(text, anchors)` 单函数
3. 实体高亮与原文词锚点会互相覆盖 → 改为逐段拼接（非实体段套锚点，实体段内也套）
4. 校验脚本自己也会写错：集合比较 `set(s) <= set('-: ')` 别写成 `>`，表头要拼在 rows 前面

### 关键发现：两类实体的原料质量完全不同
- **概念类（术语演化）原料极好**：49/49 概念 **100%** 有「思想演变」分期小节（共 77 个分期标题，如"萌芽期（1970-1989）"），100% 有「巴菲特原话精选」（**209 条带年份出处**引语），100% 有「相关概念」，84% 有「常见误区」
- **公司类（记分牌）原料差**：61 个公司文件中**只有 16 个（26%）**有「历年提及」表，合计仅 155 行。剩下 42 家要靠字面命中段落自动生成 → 质量分层严重
- 人物类：7 个文件**均无**历年提及表

### 已验证的噪音（字面匹配的坑，修之前别信全量数字）
1. **穆迪 1962-64 命中是假的** → 实际是 "（数据来源：Moody's Banks & Finance Manual, 1961）"，是引用数据源不是持仓。实体文件自己的历年提及表也标注为"数据来源引用穆迪手册"
2. **1956 有限合伙协议被算作信件** → `letters/special/` 里有 3 篇非股东信（2014 伯克希尔的过去现在与未来 / 2014 副董事长的思考 / 2025 感恩节致辞），另有 1956 合伙协议。做年份统计时须排除
3. 短英文别名（如 `GE`）有误匹配风险

### 自我修正/认错表述量（支撑「认错档案」功能）
- 明确认错（我错了/判断错误/估计错误/mistake）：16 处 / 12 个年份
- 自嘲（又蠢又有钱/愚蠢/蠢事）：119 处 / 45 个年份

### 结论
- 术语演化（概念）应排在记分牌（公司）之前做：原料 100% 现成 vs 26% 现成
- 58 家 ≥3 年公司应分层：16 家精做（有权威表），42 家自动生成骨架
- 记分牌是**最好的入口**（可读性强），术语演化是**最深的资产**（可迁移性强）—— 二者不是竞争关系，是旅程的不同阶段

### 关键修正（重要，改代码时别重犯）
1. **「历年提及」不是只有 7 家表格型** —— 第二轮统计漏判。**61 家公司全部有此小节**：格式A 表格（`\s{2,}` 分列）仅 7 家（IBM/卡夫亨氏/大都会/房地美/所罗门/穆迪/高盛），格式B「年份+引文块」54 家。解析器必须兼容两种 + 纯年份列表
2. **思想演变有 4 种写法**：`萌芽期（1970-1989）：` / `合伙人时期（1956-1969年）：`（括号里带"年"）/ `格雷厄姆的原始寓言（1949年）。`（单年+句号）/ `1967年：`（裸年份）。正则不全兼容会漏掉 24 个概念（77 → 158 分期）
3. **摘要不能机械取首句** —— 关键词在第 2 句时，摘要里看不到公司名，读者会以为是乱配。改为 `pick_sentence()` 取**含关键词的那一句**
4. **认错 reverse 类不能用"事实证明"单独判定** —— 实测抓进"事实证明，这一融资安排极为及时""事后证明是一颗绝对的明珠"等**正面句**，放在认错档案里杀伤力极大。收紧为：自带贬义词（化为乌有/烟消云散/事与愿违）或"事实证明"后 40 字内出现负面信号词。24 条 → 9 条
5. admit 类同样要求第一人称：放宽时会抓进"坦白说，我希望未来…"（普通表述）和"他们会坦诚地告诉你"（引用他人）

## 第四轮：全站跳转审计与修复（用户报"点不动/页面是死的"）

### 根因：测试盲区
smoke.js 把 `document.querySelectorAll` 桩成**空数组**——点击处理器从未被测过，这就是"看着活的实际是死的"。新写 `clicktest.js`：自建最小 DOM 引擎（真实复现 `location.hash = x` 触发 hashchange、dataset、classList、innerHTML 重解析），逐个点击每个可点元素，校验①hash 真的变了 ②落地页有真内容 ③无 undefined/NaN/[object Object]。

### 修掉的 6 类真 bug
1. **决策卡选第 1 项永不揭晓**：`if (!p)` 把选项号 0 当"没选"（falsy 陷阱）→ 改 `p === undefined`
2. **多封信年份用 prompt() 选序号** → 预览 iframe 里 prompt 被禁，点击完全无反应（用户遇到的主因之一）。新增 `#/y/<年>` 年份页路由，彻底废除 prompt
3. **`?b=N` 深链参数未剥离** → 实体页所有 snippet 点击都落"找不到这封信"（全站 7825 段提及的回跳全断）→ `route()` 统一剥离 query
4. **死链 95 处**：rules 的 src 45 条（公司名/"其他"被链到概念页）、认错档案 ent 22 条、概念页案例公司 27 条、相关概念 1 条 → 统一 `entHref()/entLink()` 按真实归属路由（概念页/公司页/原文出场页），无目标渲染纯文本不硬造链接
5. **首页 `[object Object]`**：`C.companies + ' 公司'` 把对象数组拼进字符串 → 改用 `m.companies` 计数
6. **无功能按钮按需显示**：无英文锚点的信不显示"原文字对照"、第一封信不显示"上一年"（点了没反应的观感来源）

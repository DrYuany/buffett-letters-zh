## 用户三件事

1. 阅读页「本信出现的实体」有重复项 → 去重
2. 首页在「先挑一条路」和「核心投资概念」之间插入深色板块「巴菲特午餐会」
3. 点进去是一个能对话、能调站内知识库的智能体；并要我判断「要不要上向量数据库」

## 1. 实体重复（真 bug）

`letterPage()` 里 `hit[s.name] = 0` 记的是 0，而判重写的是 `!hit[name]` —— `0` 是假值，
于是同一封信里出现几次就 push 几次，列表满屏重复。改成记 `1`。
实测：1988 信 26 条去重后 26 条；抽查前 25 封信 0 重复。

## 2. 首页入口

`.talk-banner` 深色横幅（`--bg` 深底 + 金色描边），左栏 AI 问答标签 / 茶杯线描 / 标题+BETA /
两行说明 / 「开始对话 →」，右栏三条示例问句，直接 `#/talk?q=<问题>` 落地即问。
位置在 `.paths` 之后、核心投资概念之前。520px 以下竖排、问句换行。

## 3. 对话页 `#/talk`（不引向量库）

- 检索：中文 n-gram（整段短语 w=3 / trigram 2 / bigram 1.2，虚词表 `TSTOP` 过滤）+ tf-idf +
  长度归一 + 正文段加权 0.35；实体出场段落直接 +8。语料 8,431 段 / 119 万字，单问 68–281ms。
- 优先走人工档案：概念（periods 分期）、公司（timeline 跨年记录）；认错类问题走
  `CT.corrections` 加权挑选，避免字面检索翻到「不是我的错」。
- 追问：`TALK.lastEnt / lastQ / seen`，新段落不够才回退用过的段落。
- 每条引用带年份 + `#/l/<信>?b=<段>` 深链。
- **不用向量库的理由**：这个体量字面检索几十毫秒就够；embedding 要预计算 8,431×512 向量
  （约 17 MB）随站点发出去，再加中文 embedding 模型权重，换来的只是同义召回，而主要同义词
  已经被人工概念档案和别名表覆盖。真接大模型时把 top-k 段落当上下文即可，仍不需要向量库。

## 4. 顺手修的两个真问题

- **`#app.app-page` 缺 `width:100%`**：作为 flex 子项会收缩到内容宽度，对话页在 1440 下只有
  525px 且偏右。补上后 980px 居中。
- **自动提问的定时器抢占别的页面**：`#/talk?q=` 落地后 60ms 自动问一次，而 `talkAsk` 一进门就
  `render()`。若人在这 60ms 内点走，那次 render 会把当前页整块换掉（光标/滚动位置丢失，
  DOM 节点全部作废）。加 `if (route() === '/talk')` 守卫。这是全站审计里 3 条「被遮挡」
  假阳性的真凶。

## 5. 审计工具的坑（第二次踩，记牢）

- **「被遮挡」先看 rect 是不是 0×0**：元素在测量期间被重渲染换掉时，`getBoundingClientRect()`
  全 0，中心点落在 (0,0)，`elementFromPoint` 就报成「被 sidebar-header / main-inner 遮挡」。
  已让 linkaudit 直接输出「元素已被重绘（0×0）」，不再误导。
- 判定遮挡连量三次（30/80/80ms）再下结论，入场动画期间的位移不会误伤。
- 首屏没渲染出来时重载两次再判失败（第一轮 1440 就因一次导航没跑完而整轮空转）。

## 7. 文案口径修正

首页「435 个地址」原来的括号拆分算不出 435（98+51+71+14+70+9=313），因为概念和公司
各有两套页面。改成 `98 封信 + 51 个概念 × 2 页 + 71 家公司 × 2 页 + 14 位人物 + 70 个年份
+ 9 个栏目`（=435）。审计的 446 比它多 11 条：审计把 1950–2030 全部 81 个年份都走了一遍，
其中 11 个年份没有收信。两处都已写进注释，避免以后被人「修正」成相等。

## 8. 把问答做成真 agent（用户要求：现在只是 demo，接上大模型、能联网、有记忆）

**前提：密钥绝不进前端。** 用户给了 DeepSeek 密钥，但写进 index.html 等于公开给别人刷额度，
所以必须有一个跑在本机的后端代理。新增文件：

- **`agent.js`**（无第三方依赖，Node 18+）：
  1. 静态托管 site/（顺便解决 file:// 的数据加载限制）
  2. `POST /api/chat` → SSE：事件有 start / step / delta / reset / cite / sources / note / usage / done / error
  3. 真 agent 循环：模型自己决定调什么工具、查几次，最多 6 轮、14 次工具调用；
     证据不够会自己换关键词再查（实测常到 5–8 轮工具）
  4. 9 个工具：search_letters / open_passage / letter_outline / concept_profile /
     company_timeline / corrections / web_search / open_url / remember
  5. 三层记忆：会话历史（服务端，>16 条滚窗）+ 本次已引用段落（不重复列来源）+
     长期记忆 `agent-memory.json`（remember 工具写，每次进 system prompt）
- **`_agent.key`**：密钥单独放本机文件（也支持环境变量 DEEPSEEK_API_KEY）。
- **`start.bat`**：双击启动，自动找 node、自动开浏览器。
- **`_agentcli.js`**：命令行直连 SSE 试跑，判断循环/工具/引用比在浏览器里看方便。

**模型**：只有 `deepseek-v4-pro` 和 `deepseek-flash` 两个。默认 flash（18–22 秒出答案），
前端有「深思模式」切 pro。两个都支持 tools + stream，并返回 `reasoning_content`（不展示）。

**联网**：DeepSeek 没有内置搜索，自己实现 `web_search`（Bing 解析）。
关键坑：**同一台机器上 Bing 对中文和英文查询要用两套参数** ——
中文加 `setlang=zh-CN&cc=CN`；英文必须换成 `setmkt=en-US&setlang=en&FORM=QBLH`，
否则返回的是「Windows 安全中心」「某招聘站」这种推荐位垃圾。
另外 Bing 的跳转链接 `/ck/a?...&u=a1<base64>` 要解出真实地址，GBK 页面要按声明的编码解。

**引用方案**：工具输出里带 `[[信件id|段号]]` / `[[web|网址]]`，模型照抄进正文，
前端 `fmtCite()` 渲染成能点回原文的胶囊；服务端在收尾时按"答案里真出现的标记"反查一遍
再发 `sources`，这样末尾的出处清单不会比答案本身长。

**前端改造**：`talkAsk` 分两路——服务在线走 SSE 流式（`talkPaint` 只重画那一条气泡，
不整页 render，否则输入框光标会丢）；不在线走原来的关键词检索，并且界面上明确写
「离线模式（关键词检索）」，不允许假装是 AI。新加：连接状态标签、工具步骤清单、
引用胶囊、末尾出处清单、联网/深思开关、停止按钮、遗忘按钮。
输入框和开关包在同一个 sticky 容器里（.tp-bar），否则长答案滚到一半开关就被挤出视口。

**实测**：一问「他怎么看待回购」→ 8 轮工具、11 条引用、1800 字，
引用胶囊点下去能落到「1999 巴菲特致股东信?b=141」；多轮追问接得住；
让它记住一句话后 `agent-memory.json` 真的多了条带上下文的读者画像；遗忘按钮清得掉。

**测试**：`talktest.js` 重写成模式自适应（在线测 agent 全流程 11 项，离线测降级 4 项）。
`linkaudit.js` 的 B2 和 C2 都要跳过 `#/talk?q=`（在线时一问几十秒，还会把页面拉走）。
回归（离线、1440 与 390 各一遍）：446 路由 0 异常 / 1,255 条去重链接 0 死链 /
4,743 处命中测试 0 异常 / 959 次抽样真实点击 0 失败 / 243 条侧栏 0 失败；
actaudit 74 次 0 失败 → 首页 `AUD_CLICK` 改成 959+243+74=1,276，`AUD_HIT` 仍是 4,743。

**又踩一次同类坑**：探活的 fetch 回调里调了 `render()`，把审计正在量的 `#/talk` 整页换掉，
于是报出「#/talk 上的返回链接尺寸为 0」—— 和白天那次一模一样。
修法是异步回调只更新那两处文字（`talkUpdateState()` 改状态标签 + 空态说明），绝不整页重绘。
这条要当成通用规则：**任何异步回调都不要整页 render，除非先判 route 且真的需要。**

**答案排版**：模型会混着输出 `## 小标题` / `**加粗**` / `> 引用`，前端 `fmtAns()` 逐个处理
（井号去掉并加粗）；答案底部列出「这一答引用的出处（N 条）」和
「这一答他自己查了 N 次资料、N 轮 · 用了 N tokens」—— 接的是要花钱的模型，花多少要摊给读者看。

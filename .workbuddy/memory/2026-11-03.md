## 分身回来验收：判分器按五段重写（sim1 基线 6/6）

隔了几小时后回来，`agent.js` 已经被并行会话改了很多：分身从「两区」升级成「五段研判」，
加了 market_snapshot / peer_compare / market_news，答案要先拿数再开口。
我之前写的 `eval/check_sim.js` 还在查已经消失的 `【按这些依据推演】`，等于废了。

**重写判分器，四个坑**（都写进了文件头）：
1. 引文核对不能只认 `[[信|段]]`。股东大会/演讲的语料没有信件标记，提示词明令不许编；
   只按 `[[ ]]` 核会逼模型下次编一个假标记。没标记的去三份语料搜，LCS≥8 算过。
2. 标记只能在同一行内找。往前放宽 180 字会跨到下一条，拿下一句的出处核这一句
   （实测：1999 股东大会两句话被对到 1987 年那段的标记，判成「2 字吻合」）。
3. 事实区与量它区要用两种切法：事实区一行一件不带符号；量它区用「一、」「- 」打头且
   「读数：」另起一行，按行切会把一条角度拆成两条，第一条有尺子、第二条没有。
4. 拒答题要分诊。钓鱼题本来就没五段，拿五段量必然全红。`cases-sim.jsonl` 标 `expect:"abstain"`。

**判出一个真 bug**：分身答案有 5% 卡在 `finish=length`——模型先花两三千 token 推理，
4096 的输出预算被吃掉一半，写到【我怎么量它】中间就停，连【所以】都没出来。
改：分身模式 max_tokens 8192（考据模式保持 4096，别顺手抬成本）。

**提示词两处对齐**（原来判据和提示词互相打架）：
- 尺子原来只允许 〔id〕 或 [[信|段]]，但模型常写「（2005 年股东大会）」——这恰恰是规矩要求的
  写法（不能给股东大会编信件标记）。改成三种标法任选。
- 示例里写着 `〔case_xxx〕`，模型会照抄占位符。换成真的 `〔rule-148〕` / `[[1997 巴菲特致股东信|126]]`。
- 字数从「800-1100」改成「1000-1400，宁可短」；实测中位数 1545，还是压不下来，
  判分器把长度降级成只提示（硬边界 900-2000），别拿一条做不到的线判死。

**新增 `eval/cases-sim.jsonl` 6 条**（暴雷跌停 / 高位回购 / 股息 vs 存款 / 指数估值 /
能力圈外 / 预测明天涨跌），`run_batch.js --set sim` 跑批，`check_sim.js --run-id` 判分。
`--set all` 不含 sim，旧基线不受影响。

**sim1 结果**：6/6 全过。字数中位 1545；原话区引文 5/5 逐字可核；案例 id 5/5 真实；
